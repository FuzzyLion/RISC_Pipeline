# 阶段 3：系统化验证环境

## Time Limit

建议用时：1 到 2 周  
硬上限：2 周

## 目标

把“能调通”升级成“能持续回归验证”，让每次改动都能快速发现问题。

## 详细任务

### 任务 1：建立模块级验证

1. 为 ALU、寄存器堆、控制器、Hazard Unit 编写模块级 testbench。

### 任务 2：建立处理器级验证

1. 为 CPU 顶层建立程序级测试框架。
2. 固定程序编译、镜像转换、仿真运行和结果检查流程。

### 任务 3：建立批量回归

1. 将 `riscv-tests` 中适合当前阶段的用例纳入回归。
2. 建立失败用例记录表和缺陷分类方式。
3. 编写统一回归入口脚本。

### 任务 4：评估验证增强工具

1. 评估是否引入 Cocotb。
2. 评估 Icarus Verilog 和 Verilator 的分工。

## 阶段产出

1. 模块级测试集。
2. 顶层程序级测试集。
3. 回归脚本。
4. `riscv-tests` 接入记录。
5. 缺陷跟踪表。
6. 验证工具选型结论。

## 验证要求

1. 可以一键运行基础回归。
2. 失败用例可快速定位到模块或阶段。
3. 后续新增功能不会明显拖慢验证效率。

## 风险与注意点

1. 不要只堆测试数量，要保证失败可定位。
2. 在 Cache 和 FPU 进入前，把回归框架打稳非常关键。
3. 如果后续接入 Cocotb，要保证目录结构和回归入口不会被打乱。

## 退出条件

1. 可以一键运行基础回归。
2. 失败用例可快速定位。
3. 可以进入 CSR、系统级和后续扩展阶段。
