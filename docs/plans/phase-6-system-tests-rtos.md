# 阶段 6：标准测试、RTOS 与增强项

## 目标

在主线稳定后验证系统能力，并评估后续增强特性的推进顺序。

## 建议任务

1. 扩大 `riscv-tests` 覆盖范围。
2. 统计通过率并分类失败原因。
3. 准备 RTOS 所需最小运行环境。
4. 尝试跑通基础 tick 中断和简单任务调度示例。
5. 在主线稳定后再评估 `M` 扩展、Cache、FPU。

## 增强项建议顺序

1. `M` 扩展。
2. Cache。
3. FPU。

## 设计关注点

1. RTOS 失败到底来自中断、上下文切换还是内存映射。
2. Cache 是否会破坏当前的握手式存储接口假设。
3. FPU 是否值得单独作为远期项目继续推进。

## 阶段产出

1. 标准测试通过率报告。
2. RTOS bring-up 记录。
3. 增强功能评估结论。

## 退出条件

1. 公开测试集通过情况清晰可追踪。
2. RTOS 能力边界已经明确。
3. 后续增强项的优先级有清晰结论。
