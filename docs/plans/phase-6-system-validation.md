# 阶段 6：系统级测试与软件基线

## Time Limit

建议用时：1 到 1.5 周  
硬上限：2 周

## 目标

在 CPU、CSR 和最小 SoC 都稳定后，建立系统级软件测试基线，为后续 Cache 和 FPU 引入前先锁定一个“已知正确”的版本。

## 详细任务

### 任务 1：扩大标准测试覆盖

1. 扩大 `riscv-tests` 覆盖范围。
2. 统计通过率并分类失败原因。

### 任务 2：建立软件运行基线

1. 固定一批稳定可运行的 C/汇编程序。
2. 固定编译参数、链接脚本和镜像转换流程。

### 任务 3：建立系统级回归入口

1. 将仿真级和板级可复现测试统一到回归流程。
2. 记录板级与仿真行为差异。

## 阶段产出

1. 标准测试通过率报告。
2. 系统级基线程序列表。
3. 固定版编译和运行脚本。
4. 失败问题分类表。

## 验证要求

1. `riscv-tests` 通过率可追踪。
2. 基线程序在仿真和板级都可重复运行。
3. 后续引入 Cache 和 FPU 时可以直接对比回归结果。

## 风险与注意点

1. 如果这一阶段的基线不稳定，后续 Cache 和 FPU 出问题会很难定位。
2. 本阶段重点是“冻结基线”，不是继续随意加功能。

## 退出条件

1. 已有系统能力形成稳定基线。
2. 有一套可复用的系统级回归入口。
3. 可以进入 Cache 阶段。
