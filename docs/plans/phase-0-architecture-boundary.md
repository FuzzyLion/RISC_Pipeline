# 阶段 0：第一版架构边界

## Time Limit

建议用时：3 到 5 天  
硬上限：1 周

## 目标

在写大量 RTL 之前，先把第一版 CPU 的边界、模块划分和关键接口冻结下来，避免后续反复返工。

## 本阶段固定决策

1. 第一版 ISA 固定为 `RV32I`。
2. `branch` 和 `jump` 的最终跳转判定放在 `EX` 阶段。
3. 指令侧和数据侧接口采用极简握手式解耦接口。
4. 第一版只支持最小 Machine Mode 闭环，不在本阶段引入 `M`、`F`、Cache、FPU 的具体实现。

## 详细任务

### 任务 1：冻结 ISA 与指令支持列表

1. 列出第一版必须支持的指令集合。
2. 明确第一版暂不支持的指令集合。
3. 明确第一版是否保留 `M` 扩展接口占位。

### 任务 2：冻结模块划分

1. 固定顶层模块划分：
   `pc`、`if_stage`、`id_stage`、`ex_stage`、`mem_stage`、`wb_stage`、`regfile`、`alu`、`controller`、`hazard_unit`。
2. 决定 `csr` 模块是否在此阶段就保留接口占位。
3. 明确后续 Cache 和 FPU 分别会挂在哪些现有模块边界上。

### 任务 3：冻结流水线寄存器与控制路径

1. 梳理每级流水线寄存器需要携带的数据信号和控制信号。
2. 列出跨级传递的控制信号表。
3. 约定 stall、flush、redirect、memory_wait 的优先级。

### 任务 4：冻结存储接口

1. 定义 `IF` 和 `MEM` 使用的极简存储接口信号。
2. 说明请求和响应是否允许乱序，第一版建议不允许。
3. 约定对慢速外设和未来 Cache 的兼容方式。

### 任务 5：冻结关键架构策略

1. 明确 `branch` 在 `EX` 阶段判定的依据。
2. 明确异常和中断未来如何与 flush/redirect 协调。
3. 画出顶层架构图和关键控制流图。

## 推荐接口方向

建议第一版接口至少包含：

1. `req_valid`
2. `req_ready`
3. `req_addr`
4. `req_wdata`
5. `req_wstrb`
6. `resp_valid`
7. `resp_rdata`

## 阶段产出

1. 指令支持列表。
2. 模块划分说明。
3. 流水线寄存器信号表。
4. 极简总线接口说明。
5. `branch` 在 `EX` 阶段判定的控制策略说明。
6. Cache 与 FPU 预留接入点说明。

## 风险与注意点

1. 不要在本阶段被 Cache/FPU 的细节拖走主线节奏。
2. 但必须明确它们未来接入的位置，否则后面还是会返工。
3. 接口设计不能默认“永远单周期返回”。

## 退出条件

1. 第一版功能边界已经明确。
2. 模块接口和关键控制策略不再频繁变动。
3. 可以在不继续争论架构的情况下开始写 CPU 主体 RTL。
