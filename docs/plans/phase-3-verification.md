# 阶段 3：系统化验证环境

## 目标

把“能调通”升级成“能持续回归验证”，让每次改动都能快速发现问题。

## 建议任务

1. 为 ALU、寄存器堆、控制器、Hazard Unit 编写模块级 testbench。
2. 为 CPU 顶层建立程序级测试框架。
3. 固定程序编译、镜像转换、仿真运行和结果检查流程。
4. 将 `riscv-tests` 中适合当前阶段的用例纳入回归。
5. 建立失败用例记录表和缺陷分类方式。

## 推荐工具方向

1. 第一版可以继续使用现有 Verilog testbench。
2. 如果程序级测试开始变多，推荐在本阶段评估并引入 Cocotb。
3. Verilator 可优先用于高频回归。

## 本阶段建议关注

1. 如何自动生成 `.elf`、`.bin`、`.dump`、初始化镜像。
2. 如何自动检查寄存器状态、内存结果或程序退出标志。
3. 如何让 `riscv-tests` 与自写测试统一纳入同一回归入口。

## 阶段产出

1. 模块级测试集。
2. 顶层程序级测试集。
3. 回归脚本。
4. `riscv-tests` 接入记录。
5. 缺陷跟踪表。

## 退出条件

1. 可以一键运行基础回归。
2. 失败用例可快速定位到模块或阶段。
3. 后续新增功能不会明显拖慢验证效率。
